# Sytra Studio 1.3.0 Release Notes & Migration Guide

Sytra Studio **1.3.0** integrates and hardens the core local AI studio workflows across training, dataset curation, model merging, downloading, chat/MCP/sandboxes, and inference preferences.

## Highlights

### 1. Sytra-Helix Layer-Streamed MoE Trainer
- **Multi-architecture support**: Layer-streamed SFT now supports `mixtral`, `qwen2_moe`, `qwen3_moe`, `deepseek_v2`, and `deepseek_v3` checkpoints, including shared experts (`shared_expert` / `shared_experts` and `shared_expert_gate`), MLA projections (`DeepseekV2`/`V3`), and transformers 5.x fused 3D MoE expert tensors via slice-level safetensors loading (`TensorSlice`).
- **Pre-quantized 4-bit and 8-bit checkpoints**: Accepts `bitsandbytes` 4-bit (`nf4` and `fp4`, single and double quantization, high-nibble-first compatible) and 8-bit (`SCB` per-row scaled `int8`) checkpoints natively via `sytra_runner.helix_quant`, alongside local NF4/Int8 quantization (`FrozenNF4Linear`, `FrozenInt8Linear`).
- **Triton fused kernels**: Integrated `fused_nf4_lora_linear` (forward + backward dX/dA/dB) and `chunked_cross_entropy_sum` (`sytra_runner.helix_triton_ops`) into the Helix NF4 and SFT training loop, avoiding full `[N, V]` FP32 logit materialization on CUDA.
- **Paged 8-bit optimizer**: Uses `HelixPagedAdamW8bit` (bridging CPU-resident layer-streamed LoRA parameters to `bitsandbytes.optim.PagedAdamW8bit` on CUDA) by default when CUDA + `bitsandbytes` are available, with safe `torch.optim.AdamW` fallback on CPU or when requested.
- **Rectangular FlexAttention packing, memmap dataloader & training schedules**: Reduced FlexAttention block-index growth from quadratic to `O(blocks * W)` rectangular sliding window indexing (`helix_packing.py`), added CPU/eval `packed_causal_4d_mask`, persistent memory-mapped pre-tokenized datasets (`helix_dataset_mmap.py`), `epochs` scheduling alongside `max_steps`, `completion_only_loss=False`, and `sigmoid`/`softmax` router load balancing.

### 2. Dataset Fabric & Curation
- Strict non-overlapping `train_dataset` and optional `val_dataset` slots across JSONL, Parquet, and multi-shard JSON manifests.
- Native tokenizer `min_tokens` / `max_seq_length` counting (`token_counting: "native_tokenizer"` vs explicit fallback), exact/near-duplicate filtering, n-gram repetition filtering, and opt-in syntax sanitization (`sanitize_syntax: false` by default).
- 13-gram benchmark decontamination scoped explicitly to the local benchmark files supplied by the user.
- Optional local semantic filtering (`dataset_semantic.py`) with strict JSON extraction and multimodal/causal LM support.

### 3. Model Merger & MoE Builder
- Verified environment provisioning (`merge-env` with `transformers 4.57.6`, `accelerate 1.0.1`, `mergekit 0.0.5.1`), `sytra_runner.moe_exec` shared-expert fix, spherical/SLERP/NuSLERP/TIES/DARE algorithms, and atomic publishing. See [MoE Builder Verification](../MOE_BUILDER_VERIFICATION.md).

### 4. Downloader
- Xet/CAS stall detection (`_DownloadStalled`) with safe HTTP multi-range fallback (`http_ranges.py`), proxy and cross-origin redirect credential stripping, `200 OK` vs `206` handling, `ETag`/size change recovery, SHA-256 verification, atomic rename, and redacted telemetry.

### 5. Chat, Skills, MCP & Sandboxes
- Multi-server stdio MCP registry with SQLite FTS5/BM25 search, cursor pagination, `notifications/tools/list_changed`, preemptive/concurrent cancellation, bounded tool-argument repair (`toolArguments.ts`), and fail-closed JavaScript sandbox verification (`DenoSandbox`, requires trusted local `deno`).
- Workspace-confined `@skill` injection (up to 8 skills per conversation), conversation branching at any message, abort/steer handling, and tightened workspace/JSON checks in `tool_engine.py`.
- Chat and Datasets follow the shared interface locale and appearance preferences. Local agent schedules run while the Chat tab is open, and the regression test verifies recurrence, memory writes, and timer cleanup.
- Web Search uses the Wikimedia Action API for Wikipedia results by default. Configure `BRAVE_SEARCH_API_KEY` for general web search. The separate [Sytra Cloud Agent](../../cloud-agent/README.md) supports approved browser interaction on configured HTTPS origins and optional cloud schedules. The browser smoke test passed in Vercel Sandbox. Model execution requires AI Gateway activation on the linked Vercel project.

### 6. Inference & Per-Model Preferences
- Validated KV-cache quantization (`fp16`, `q8_0`, `q4_0` where supported, with explicit FlashAttention and quality-impact notices), hardware memory guardrails, hybrid CPU/GPU MoE offload planning, JIT TTL idle unloading, and per-model/global temperature application across UI and external OpenAI/Anthropic proxy clients. See [Chat Model Preferences](../CHAT_MODEL_PREFERENCES.md).

### 7. Zero-NPM `.exe` Install & Direct MCP Setup
- Standalone `sytra-studio` and `sytra-mcp` executables now resolve `~/.sytra` cleanly when launched outside the repository and automatically deploy the embedded `runner/` scripts without requiring NPM or Node.js.
- Added native installers ([scripts/install.ps1](../../scripts/install.ps1) and [scripts/install.sh](../../scripts/install.sh)), portable release bundles with `SHA256SUMS.txt` in `.github/workflows/release.yml`, CLI setup subcommands in `sytra-mcp` (`install`, `uninstall`, `status`, `print-config`), and an **MCP Integration (No NPM)** card in Settings.

## Migrating from 1.2.5 to 1.3.0

1. **Workspace environments**: Existing `.sytra-envs/merge-env` provisions from 1.2.x with `transformers 5.x` should be reprovisioned (or removed so the host reprovisions `PROVISION_SCHEMA = 2`, `MERGE_RUNTIME_REVISION = 2`).
2. **Helix checkpoints & configs**:
   - Helix configs no longer fail validation when `epochs` is set (instead of `max_steps`), when `quant_bits: 8` (`qlora`) is chosen, or when `completion_only_loss: false` is set.
   - Adapter checkpoints quantized with 8-bit Int8 or loaded from pre-quantized `bitsandbytes` weights emit `sytra-helix-quant.json` (while NF4-cached runs continue emitting `sytra-helix-nf4.json`). Resume checks enforce matching base quantization settings.
3. **Host security & contracts**:
   - `ResourceGuard::check_train` now rejects unknown CPU RAM (`total_ram_mb == 0`) with `UnknownHardware`, matching GPU and merge guards.
   - Ollama `Modelfile` export sanitizes CR/LF in `FROM` paths as well as `TEMPLATE` and `PARAMETER stop`.
   - Dataset CSV/Parquet materialization streams in 2048-row chunks via atomic temp files.

## Known Limitations & Hardware Scope

- Local GPU measurements in this release cycle were recorded on a single **NVIDIA GeForce RTX 3060 (12 GB VRAM)** with ~16 GiB system RAM on Windows. Smaller VRAM envelopes (such as 4 GB or 8 GB GPUs) and very large multi-node models remain hardware profiles rather than empirically benchmarked guarantees on this machine.
- The JavaScript sandbox (`DenoSandbox`) remains disabled with an explicit error unless `deno` is installed and passes its isolation self-test; host Python code execution in `UniversalToolEngine` remains disabled until a sandboxed Python/WASM runtime is configured.
- 13-gram benchmark decontamination only checks local benchmark files supplied explicitly via `benchmark_files`; MMLU, GSM8K, HumanEval, ARC, or MATH are not bundled.
